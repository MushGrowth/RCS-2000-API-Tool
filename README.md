# RCS-2000接口调用工具 V1.0 使用说明

## 1. 工具简介

项目名称：`RCS-2000接口调用工具`

软件版本：`V1.0`

`RCS-2000接口调用工具` 是专为海康 RCS-2000 平台设计的 Windows 图形化接口调用工具，面向项目实施、系统联调、现场调试、批量数据验证和问题排查。

工具支持 RCS 3.x 和 RCS 4.x 接口。实际可调用的接口、字段要求、URL 和返回结果，应以当前项目部署的 RCS-2000 版本及配套接口文档为准。

工具支持：

- RCS 3.x / RCS 4.x 版本切换。
- 单次调用接口。
- 通过 Excel 批量调用接口。
- 预置接口自动填充字段配置。
- 普通字段、对象字段、数组对象字段。
- JSON 数组和 JSON 对象直接填写。
- 必填、条件必填、选填提示。
- 字段可通过“☰”图标拖动排序，列号自动同步。
- 修改 Excel 列号时自动插入对应位置，其他列号依次顺延。
- 暂停、继续、停止批量调用。
- 失败行查看、清空和导出。
- 界面日志按需导出，默认不写入本地文件。
- Excel 模板导出。
- 配置自动保存和恢复。
- 软件内置使用说明按钮。

## 适用场景

- RCS-2000 与 WMS、MES、WCS 等上层系统的接口联调。
- 任务生成、继续、取消、优先级设置等接口验证。
- 货架、容器、仓位、位置及物料关系接口调试。
- 使用 Excel 批量构造和发送测试数据。
- 查看请求、响应和失败数据，辅助现场问题排查。

## 源码运行与打包

建议使用 Python 3.12。

安装依赖：

```bash
python -m pip install -r requirements.txt
```

运行源码：

```bash
python rcs_api_call_tool.py
```

Windows 单文件打包：

```powershell
python -m PyInstaller --noconfirm --clean --onefile --windowed `
  --name "RCS-2000接口调用工具" `
  --icon ".\assets\rcs2000-icon.ico" `
  --version-file ".\version_info.txt" `
  --add-data ".\assets\rcs2000-icon.ico;assets" `
  rcs_api_call_tool.py
```

本地配置文件和 `dist` 构建产物不会提交到源码仓库。

## 3. 界面区域说明

界面主要分为以下区域：

- 顶部配置区：RCS版本、调用方式、选择接口、使用说明。
- URL配置区：IP、端口、接口后缀/方法名、完整URL。
- 批量数据导入区：批量模式下选择 Excel。
- 字段配置区：配置字段、嵌套字段、字段值。
- 操作区：开始执行、暂停执行、停止执行、清空日志、导出日志。
- 日志区：显示发送报文、应答报文和执行结果。
- 失败行区：展示失败行，支持查看明细、清空和导出。

## 4. 使用说明按钮

界面右上角有 `使用说明` 按钮。

点击后会弹出一个可滚动窗口，显示软件内置的用户使用说明。

该说明适合现场使用人员快速查看，不需要打开 README 文件。

## 5. RCS版本切换

顶部 `RCS版本` 下拉框支持：

- `RCS 3.x`
- `RCS 4.x`

默认版本为 `RCS 3.x`。

切换版本时：

- 当前字段配置会清空。
- 选择接口下拉框会切换为对应版本的接口。
- 程序自动选中该版本第一个预置接口。
- 自动加载对应字段配置。
- 自动更新端口和完整 URL。

如果当前正在执行任务，切换版本前会提示：

```text
切换版本将清空当前状态，是否继续？
```

## 6. URL拼接规则

### 6.1 RCS 3.x

URL规则：

```text
http://IP:8182/rcms/services/rest/hikRpcService/接口方法名
```

示例：

```text
IP：10.6.11.13
端口：8182
接口后缀/方法名：bindPodAndBerth
完整URL：http://10.6.11.13:8182/rcms/services/rest/hikRpcService/bindPodAndBerth
```

### 6.2 RCS 4.x

URL规则：

```text
https://IP:443/rcs/rtas/接口路径后缀
```

示例：

```text
IP：10.6.11.13
端口：443
接口后缀/方法名：api/robot/controller/task/submit
完整URL：https://10.6.11.13:443/rcs/rtas/api/robot/controller/task/submit
```

说明：

- IP 可以手动修改。
- 端口可以手动修改。
- 接口后缀/方法名可以手动修改。
- 完整URL也可以手动修改。
- 最终执行时以完整URL输入框为准。

## 7. 调用方式

顶部 `调用方式` 下拉框支持：

- `单次`
- `批量`

默认调用方式为 `单次`。

### 7.1 单次调用

适合临时测试接口。

使用步骤：

1. 选择 RCS 版本。
2. 选择接口。
3. 检查 IP、端口和完整URL。
4. 在字段配置右侧 `字段值` 中填写参数。
5. 点击 `开始执行`。
6. 查看日志中的发送报文和应答报文。

单次调用不需要选择 Excel。

### 7.2 批量调用

适合通过 Excel 批量调用接口。

使用步骤：

1. 选择 RCS 版本。
2. 选择接口。
3. 检查字段配置。
4. 点击 `导出Excel模板` 生成模板。
5. 按模板填写 Excel 数据。
6. 选择 Excel 文件。
7. 点击 `开始执行`。
8. 程序逐行调用接口。

批量调用时，每一行 Excel 数据对应一次接口调用。

字段配置不再显示“字段1、字段2”等冗余序号。可拖动每行左侧的 `☰` 图标调整顺序；也可直接修改 `Excel列号`，字段会自动移动到目标位置，原位置及目标位置之间的字段会依次顺延，列号始终保持连续且不重复。

## 8. 预置接口

`选择接口` 下拉框会根据当前 RCS 版本展示不同接口。

选择接口后自动填充：

- 接口后缀/方法名。
- 完整URL。
- 字段配置。
- 字段要求。
- 嵌套字段层级。

自动填充后，仍可以手动修改：

- IP。
- 端口。
- 接口后缀/方法名。
- 完整URL。
- 字段顺序。
- Excel列号。
- 是否有嵌套。
- 嵌套层级。
- 字段名。
- 字段值。

字段 `要求` 为只读，不允许手动修改。

## 9. 字段配置说明

字段配置每一行包含：

- `拖动`：按住后上下移动字段顺序。
- `字段X`：字段序号。
- `Excel列号`：批量调用时读取 Excel 的列号。
- `有嵌套`：该字段是否为嵌套字段。
- `嵌套层级`：对象或数组对象的父级路径。
- `字段名`：普通字段名或子字段名。
- `要求`：只读显示必填性。
- `字段值`：单次调用时填写参数值。
- `删除`：删除字段配置。

## 10. 字段要求

字段要求分为：

- `必填`
- `条件必填`
- `选填`

校验逻辑：

- 必填字段为空时，程序会阻止执行。
- 条件必填字段只做提示，不做强制拦截。
- 选填字段为空时，不会写入请求报文。

条件必填不强制拦截，是因为它依赖业务规则，例如：

- 二选一。
- 四选一。
- 某字段为特定值时必填。

这类逻辑需要使用人员根据接口实际规则填写。

## 11. 普通字段

普通字段不需要勾选 `有嵌套`。

示例：

| Excel列号 | 有嵌套 | 嵌套层级 | 字段名 | 要求 |
|---|---|---|---|---|
| 1 | 不勾选 | 空 | `podCode` | 必填 |
| 2 | 不勾选 | 空 | `positionCode` | 必填 |

生成报文：

```json
{
  "podCode": "P001",
  "positionCode": "A001"
}
```

## 12. 嵌套对象字段

对象字段示例：

```text
targetRoute.type
targetRoute.code
```

字段配置：

| 有嵌套 | 嵌套层级 | 字段名 |
|---|---|---|
| 勾选 | `targetRoute` | `type` |
| 勾选 | `targetRoute` | `code` |

生成报文：

```json
{
  "targetRoute": {
    "type": "SITE",
    "code": "S001"
  }
}
```

## 13. 数组对象字段

数组对象字段示例：

```text
data[0].robotTaskCode
data[0].sequence
```

字段配置：

| 有嵌套 | 嵌套层级 | 字段名 |
|---|---|---|
| 勾选 | `data[0]` | `robotTaskCode` |
| 勾选 | `data[0]` | `sequence` |

生成报文：

```json
{
  "data": [
    {
      "robotTaskCode": "T001",
      "sequence": "1"
    }
  ]
}
```

说明：

- `[0]` 表示数组第一个对象。
- `[1]` 表示数组第二个对象。
- 如需多个对象，可复制字段配置并修改索引。

## 14. JSON数组和JSON对象

部分字段本质是数组，例如：

- `robots`
- `zoneCodes`

这类字段按普通字段处理即可。

字段值中填写 JSON 数组：

```json
["R001","R002"]
```

部分字段本质是 JSON 对象，例如：

- `extra`

字段值中填写 JSON 对象：

```json
{"key":"value"}
```

程序会自动识别 JSON 数组和 JSON 对象。

## 15. RCS 3.x 与 RCS 4.x 差异

### 15.1 RCS 3.x

3.x 请求报文会自动加入：

```json
{
  "reqCode": "自动生成的32位唯一值"
}
```

不需要在字段配置中手动添加 `reqCode`。

### 15.2 RCS 4.x

4.x 请求报文不会发送 `reqCode`。

4.x 每次调用会自动添加请求头：

```text
X-lr-request-id
```

该值：

- 最大 16 字节。
- 每次调用唯一。
- 程序自动生成。

## 16. 成功判断

以下任一响应视为成功：

```text
code == 0
code == "0"
code == "SUCCESS"
```

其他情况视为失败。

## 17. 字段拖动排序

字段行左侧有 `拖动`。

使用方式：

1. 鼠标按住 `拖动`。
2. 上下移动到目标位置。
3. 松开鼠标。

拖动后：

- 字段顺序会变化。
- Excel列号会自动按顺序重新编号。
- 导出模板列顺序会变化。
- 执行读取 Excel 的顺序会变化。
- 配置保存顺序也会变化。

## 18. 鼠标滚轮

字段配置区域支持鼠标滚轮。

当字段较多时，可以：

- 使用右侧滚动条。
- 使用鼠标滚轮上下滚动。

## 19. 导出Excel模板

点击 `导出Excel模板` 后，会生成一个 Excel 文件。

模板第一行是字段名。

字段顺序取当前界面顺序。

嵌套字段会显示完整路径，例如：

```text
targetRoute[0].type
```

## 20. 暂停、继续、停止

### 暂停执行

暂停后续接口调用。

当前正在调用的接口会等待返回。

暂停后 `开始执行` 按钮会变成 `继续执行`。

### 继续执行

点击 `继续执行` 后，从暂停位置继续。

### 停止执行

停止后续接口调用。

当前正在调用的接口会等待返回。

下次开始会重新从第一行执行。

## 21. 日志和失败行

日志区会显示：

- 当前执行进度。
- 发送报文。
- 应答报文。
- 成功或失败信息。

失败行列表会记录失败数据。

点击失败行后，可以查看：

- 发送报文。
- 应答报文。
- 失败原因。

点击 `清空失败行` 可清除当前失败列表和右侧失败明细；点击 `导出失败行` 可导出失败记录。

日志默认只显示在界面中，不会自动保存到本地。需要保留日志时，点击操作区最右侧的 `导出日志`，选择路径后导出为 TXT 文件。`清空日志` 位于 `导出日志` 左侧，用于清除当前界面日志。

## 22. 配置保存

关闭软件时自动保存配置。

保存内容包括：

- RCS版本。
- IP。
- 端口。
- 接口后缀。
- 完整URL。
- 选择接口。
- 调用方式。
- Excel路径。
- 字段配置。
- 字段值。

下次打开会自动恢复。

## 23. 常见问题

### 23.1 为什么4.x没有reqCode？

4.x不需要发送 `reqCode`。

程序会改为发送请求头 `X-lr-request-id`。

### 23.2 条件必填为空为什么还能执行？

条件必填依赖业务场景。

例如二选一、四选一、某字段等于某值时必填。

工具只提示，不强制判断。

### 23.3 选填字段为空会发送吗？

不会。

选填字段为空时不会写入请求报文。

### 23.4 单次调用需要Excel吗？

不需要。

单次调用直接填写字段值即可。

### 23.5 批量调用需要字段值吗？

不需要。

批量调用从 Excel 中读取字段值。

## 24. 注意事项

- 运行电脑需要能访问接口服务器。
- Excel 文件不要被其他程序锁定。
- 字段名不能为空。
- 不要手动配置 `reqCode`。
- 4.x 的数组字段可以直接填写 JSON 数组字符串。
- 4.x 的 `extra` 可以直接填写 JSON 对象字符串。
